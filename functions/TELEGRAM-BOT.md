# Учебный Telegram-бот — что сделано и что нужно сделать вам

Запрос автора 2026-07-27: «чтобы ученики могли обучаться с телеграм-бота».

## Что умеет бот

| Раздел | Что делает |
|---|---|
| 📖 Модули | Список модулей → уроки → текст книги постранично, кнопки «назад/дальше» |
| 📝 Экзамены | Вопрос и четыре кнопки, порог 70 %, разбор неверного ответа сразу |
| 🏋 Практика | Намерение, шаги, счётчик повторений кнопкой, отметка дня, запись наблюдения |
| 📊 Прогресс | Модули, книги, упражнения, средний балл |
| 🗓 Что сегодня | Начатые многодневные упражнения, не отмеченные за сегодня |
| 💬 Наставник | Вопрос уходит вам, ваш ответ реплаем возвращается ученику |
| 📝 Запись в школу | Регистрация прямо в боте, без сайта — имя и почта |

Утром в 8:00 по Москве бот пишет только тем, у кого есть незакрытая серия
дней. Рассылки «зайди позанимайся» всем подряд нет намеренно: её отключают
на третий день, а вместе с ней перестают читать и всё остальное.

## Главное про устройство

**Один аккаунт, а не два.** Бот пишет в ту же запись `students/{uid}`, что и
сайт. Прошёл экзамен в Telegram — на сайте он тоже сдан.

**Регистрация в боте** (запрос автора 2026-07-27: «для тех, кто не может
попасть на сайт»). Человек нажимает «Записаться в школу», называет имя и
почту — бот заводит НАСТОЯЩУЮ учётную запись Firebase через Admin SDK и
профиль ученика той же формы, что при регистрации на сайте.

Учётная запись создаётся сразу, а не «запись в базе со случайным номером»,
именно ради одного аккаунта: иначе в день, когда человек всё-таки откроет
сайт и зарегистрируется там, у него появился бы второй аккаунт, а первый со
всем прогрессом остался бы недостижимым.

Пароль не спрашивается. Когда сайт понадобится, кнопка «Пароль для входа на
сайт» выдаёт одноразовую ссылку Firebase на его установку — аккаунт и
прогресс те же.

**Если названная почта уже занята**, бот НЕ привязывается к ней молча:
назвать чужой адрес может кто угодно, и это был бы захват чужого прогресса.
Вместо этого вам приходит просьба с кнопкой «🔗 Привязать» — решаете вы.

**Привязка существующего аккаунта.** Кабинет ученика → «Привязать Telegram» → одноразовый код,
живёт 15 минут → ссылка `t.me/ruyka_school_bot?start=КОД` → бот связывает
аккаунты. Сам факт привязки (`tgChatId`) ставит только бот: ученику это поле
запрещено правилами, иначе он привязал бы свой Telegram к чужой записи.

**Пейвол проверяет сам бот.** Правила Firestore ограничивают браузер, но не
Admin SDK, под которым работают функции. Проверка одна — `paid || fullAccess`
(функция `hasFullText`). Неоплативший получает тот же вводный отрывок, что и
на сайте, и кнопку «Открыть полный курс».

## Что нужно сделать вам

Всё ниже выполняется один раз, из папки `functions/`.

**1. Секрет вебхука.** Раньше вебхук принимал POST от кого угодно. Теперь
через него идут данные учеников, поэтому нужен секрет:

```
firebase functions:secrets:set TG_WEBHOOK_SECRET
```

Введите любую случайную строку (например, 32 символа) и запомните её.

**2. Токен учебного бота @ruyka_school_bot и ваш chat_id:**

```
firebase functions:secrets:set TG_BOT_TOKEN
firebase functions:secrets:set TG_CHAT_ID
```

Токен старого бота, лежавший в репозитории, нужно отозвать у @BotFather:
он читался по raw-ссылке GitHub и с ним посторонний мог писать от имени
школы.

Для локального запуска эмулятора те же значения кладутся в `functions/.env`
— образец с пояснениями лежит рядом, в `functions/.env.example`. Сам `.env`
закрыт в `.gitignore` и в репозиторий не попадает.

**3. Деплой:**

```
firebase deploy --only functions
firebase deploy --only firestore:rules
```

Правила обязательны: без них поле `tgChatId` останется открытым для записи
из браузера, а коллекция `tgUsers` — незакрытой.

**4. Привязать вебхук с секретом.** Адрес функции покажет деплой
(`telegramWebhook`). Откройте в браузере, подставив своё:

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=<АДРЕС_ФУНКЦИИ>&secret_token=<СЕКРЕТ>
```

Ответ должен быть `{"ok":true,"result":true,...}`.

**5. Кнопка меню в боте** (необязательно, но удобно) — у @BotFather команда
`/setcommands` для вашего бота:

```
start - начать
menu - главное меню
today - что сегодня
progress - мой прогресс
```

## Проверка после деплоя

1. Откройте кабинет ученика на сайте → «Привязать Telegram» → перейдите по
   ссылке. Бот должен ответить «Аккаунт привязан».
2. 📖 Модули → Модуль 1 → любой урок. Оплатившему приходит полный текст,
   неоплатившему — отрывок и предложение открыть курс.
3. Сдайте экзамен книги в боте и обновите страницу этой книги на сайте —
   он должен быть отмечен сданным там же.
4. Напишите вопрос через «Спросить наставника» — он придёт вам с пометкой
   `#uid`. Ответьте на это сообщение реплаем — ответ уйдёт ученику.

## Если что-то менялось в курсе

Данные для бота — сгенерированный файл `functions/course-data.json`. После
любой правки модулей, уроков или упражнений его нужно пересобрать и
задеплоить функции заново:

```
node scripts/build-course-data.mjs
firebase deploy --only functions
```

Руками этот файл не правят — он собирается из тех же `pages/js/modules-data.js`
и `pages/js/assignments-data.js`, что читает сайт.

## Проверка логики без Telegram

```
node scripts/smoke-tg-bot.cjs
```

Прогоняет 25 сценариев на заглушках: привязка, просроченный код, замок
модуля, пейвол, экзамен целиком, замок упражнения, счётчик, отметка дня,
наблюдение, вопрос наставнику и ответ на него.

## Что стоит знать отдельно

Файлы экзаменов (`content/exams/*.md`) лежат в открытом репозитории вместе
с отмеченными правильными ответами — так было и до бота, потому что сайт
читает их из браузера. Кто заглянет в репозиторий, увидит ответы. Если это
важно, экзамены нужно переносить в Firestore тем же способом, что и платные
тексты книг, — это отдельная задача.
